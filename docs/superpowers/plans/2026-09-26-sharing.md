# Sharing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an item's owner share it (with its subtree) read-only or read/write with every user of the deployment; each member sees it in their own tree via a mount.

**Architecture:** A shared subtree moves into its own Firestore partition `shares/{id}` (same layout as `users/{email}`); `tenant` binds a *partition* next to the *user* so all existing db code runs unchanged inside a share. Members hold a `mount` todo (same id as the share root) in their own partition for position; the server splices share trees into each member's tree and tags nodes with `share`. One `migrate_subtree` routine moves subtrees between partitions for share, unshare and cross-edge drags.

**Tech Stack:** FastAPI, google-cloud-firestore (emulator for tests), pytest, vanilla JS (UMD modules), `node --test`.

**Spec:** `docs/superpowers/specs/2026-09-26-sharing-design.md`

## Global Constraints

- Tests run only against the Firestore emulator: `scripts/test.sh` (Python), `node --test tests_js/*.test.js` (JS). Baseline before this plan: 412 Python, 282 JS passing.
- Must stay inside the GCP free tier: no always-on CPU, no new Scheduler jobs, no new billed API. Any change that raises reads/writes is stated in the commit message and `docs/okf/principles.md`.
- Firestore transaction cap: batches of ≤200 writes (`CALENDAR_SYNC_BATCH` pattern).
- Shareable types: `todo`, `list`, `project`, `note`. Never `calendar` / `calendar_event` inside a share. Never a `mount` inside a share.
- Share size cap: 2,000 nodes.
- View-state TTL: 90 days. Unshared tombstone lifetime: 30 days.
- Every commit that changes behaviour updates the affected `docs/okf/` files, bumps their `timestamp`, and appends a line to `docs/okf/log.md`.
- Bump `APP_VERSION` in `web/app.js` and every `?v=` in `web/index.html` together whenever client files change.
- Everything user-visible from sharing is behind `SHARING_ENABLED` (env, default off) until Task 13.
- Never remove a user-facing feature; update `docs/okf/features/ui-inventory.md` for every added control.

### Deviations from the spec (decided while planning)

- **Freeze scope:** the migration freeze covers the whole *source partition* (every write there gets 503 `migrating` for the few seconds a migration runs), not only the moving ids. Simpler, and at family scale the window is seconds.
- **Heads-up fan-out:** Cloud Tasks are already one per todo (`tasks._task_name`), so the task body gains `partition` and the handler fans out to members, rather than one task per member.
- **Mount position ops skip `If-Match`:** a mount's position is per-person, so reparent/move of a mount is last-write-wins (the merged node's `version` is the share root's content version).

## Review Focus

1. **An owner's other device replaying a content edit against a root that became a mount.** Expected: the edit lands on the share root, not on the mount doc. Test in Task 7 (`test_content_op_on_mount_is_redirected_to_share`).
2. **A member edits while the owner shares/unshares (migration in progress).** Expected: 503 `migrating`, retried, applied after. Test in Task 6 (`test_write_during_freeze_is_503`).
3. **Duplicate replay of an op committed before a migration.** Expected: stored outcome, not applied twice. Test in Task 7 (`test_replay_of_pre_share_commit_is_not_reapplied`).
4. **Unshare while a recipient's mount is collapsed / placed deep in their tree.** Expected: mount vanishes from their tree, no orphan children, no 500. Test in Task 8 (`test_unshared_mount_is_hidden`).
5. **Read-only member's client somehow sends a write (old client, crafted request).** Expected: 403 `read only`, nothing written. Test in Task 5 permissions matrix.

```python
_partition: contextvars.ContextVar[str | None] = contextvars.ContextVar("tenant_partition", default=None)

def partition() -> str:

    return _partition.get() or f"users/{current()}"

def reset_partition(token: contextvars.Token) -> None:

    token = set_partition(path)
    try:
```

```js
let knownRevs = null; // {partition: rev}
function sameKeys(a, b) { const ka = Object.keys(a), kb = Object.keys(b); return ka.length === kb.length && ka.every((k) => k in b); }
function observeRev(prev, rev, partition) {
  if (prev == null || rev == null) return;
  const key = partition || ownPartition();
  const known = knownRevs && knownRevs[key];
  if (known != null && prev > known) { stale = true; log("stale", `remote write detected on ${key}`); }
  if (!knownRevs) knownRevs = {};
  if (known == null || rev > known) knownRevs[key] = rev;
}
function noteRemoteRevs(revs) {
  if (!knownRevs || !sameKeys(knownRevs, revs) || Object.keys(revs).some((k) => revs[k] > knownRevs[k])) stale = true;
}
```

```python
class MigrationError(Exception):  # .detail: "crosses share boundary" | "too large" | "not eligible"
    ...

def migrate_subtree(src: str, root_id: str, dst: str, *, dst_parent: str | None, index: int | None,
                    kind: Literal["share", "unshare", "move"], mode: str | None = None,
                    crash_after: str | None = None) -> None
```

- Freeze record in `{src}/meta/rev` field `migrating`: `{kind, src, dst, root_id, dst_parent, index, mode, user, step, lease_until}`; `step ∈ {"frozen","blobs","copied","switched","done"}`; lease 2 minutes.
- `run_atomic` raises `HTTPException(503, "migrating")` when the rev doc has a live `migrating` and the contextvar `_migration_ctx` is not set.
- `share`: dst = `shares/{root_id}`; writes share doc `{state: "migrating"}` first; copied root gets `parent_id=None, order_idx=0`; switch overwrites `src/todos/{root_id}` with a mount doc `{todo_id, title: "", type: "mount", parent_id, order_idx, version: 1, deleted: False, create_date}` (same position); share state → `active`; `shares.bump_meta_rev()`.
- `unshare`: src = `shares/{id}`, dst = `users/{owner}`; the root takes the owner's mount position (read the mount doc), overwriting it; share state → `unshared`, `returned_to = owner`.
- `move`: root goes to `dst_parent`/`index` in dst, dst siblings renumbered 0..n.
- Validation (before freezing): all nodes' types shareable when dst is a share; no `mount`; size ≤ 2000; for `share`, root not already inside a share and not itself a mount.
- Every step idempotent (ids preserved; `set` overwrites). `crash_after` raises `RuntimeError("injected")` after that step (tests only).

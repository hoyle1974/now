- **Digest** (`plan_device`, pure): one per device per local day: "3 due today" plus the first three titles, listing every open todo [due today or overdue](due-time.md); a marker-only (silent) run when nothing is due. The Scheduler decides *when* it runs; the device's timezone only decides which day "today" is, and there is no hour gate, so a manual `scheduler jobs run` at any time sends the day's digest once.
- **Heads-ups** (`app/tasks.py`, `push.run_heads_up`): one **Cloud Task** per *timed* todo (not date-only), delivered 1 hour before it is due to `POST /internal/notify-todo` ("Due at 3:00 PM, in about an hour"). A task is made when a todo with a timed due date whose heads-up falls within the next 24 hours is **saved** (create, edit, undelete, spawned repeat, split children; best-effort, in a background task after the response so a slow Cloud Tasks call never delays a save, and never fails it; collapse-only edits skip it) and again by the daily run (safety net, all todos due soon). Both make the same task: its name is `soon-<todo_id>-<hash of the due time>`, so creating it twice is a no-op. The task carries only the todo id and the due time it was made for; the handler re-reads the todo and stays silent (200, no retry) if it is done, deleted, gone or its due time changed, so a moved due time simply gets a new task. A due time is a bare wall-clock time, so the instant is computed in the **most recently seen device's timezone** (`home_tz`); with no device, nothing is scheduled. A heads-up is skipped for a device where the due time has already passed.
- **Devices:** the app posts its FCM token, IANA timezone and platform to `POST /push/devices` at each launch (`web/push.js`), so travel just works ([routes](../api/routes.md)). `POST /push/devices/unregister {token}` removes one. Collections `push_devices` and `push_sent` ([Firestore](../data/firestore.md)).
- **Trigger:** Cloud Scheduler job `now-notify` (`0 9 * * *`, `America/Los_Angeles`; every 10 minutes until 2026-09-21) calls `POST /internal/notify` with a Google OIDC token, and Cloud Tasks queue `now-reminders` (max 3 attempts) calls `POST /internal/notify-todo` with the same caller identity. `require_user` lets those two paths through only for a token whose audience is env `NOTIFY_AUDIENCE` and whose email is env `NOTIFY_CALLER`; either unset = off, and a Firebase login is rejected there ([auth](../ops/widget.md)). Heads-ups are off unless env `REMINDER_QUEUE` (full queue path) is also set. Cost: Cloud Tasks bills API calls and deliveries, first 1 million a month free (about 3 per timed todo), so effectively $0.
- **Multi-user (2026-09-21).** `/internal/notify` is still the one Scheduler job; the route (`app/routes/notifications.py`) loops every email in `auth.ALLOWED_EMAILS`, binding each with `tenant.as_user` before calling `push.run_notify`, and sums the per-user `{devices, sent, scheduled}` into the response — one user's exception is logged and skipped, never blocking the rest. A heads-up task's body now carries `user` (`app/tasks.py:create_task` writes `tenant.current()` into it); `/internal/notify-todo` binds that user before calling `push.run_heads_up`, falling back to `auth.owner()` when `user` is absent (a task queued before this change) and rejecting (400) a `user` outside `ALLOWED_EMAILS`. Budget alerts always bind the owner (see below); registration and unregistration run under whichever user is bound to the request.
- **Cost guard:** the run reads only devices and todos due before now+2 days (query `done==false, deleted==false, due_date<cutoff`, composite index in `firestore.indexes.json`), and nothing at all with no device.
- **No duplicates:** the marker (`digest:{local date}:{device}` or `soon:{todo}:{due}:{device}`) is written *before* the send, so a failure loses one push rather than repeating it. Markers expire after 3 days by Firestore TTL on `expires_at`. FCM `UnregisteredError` or `SenderIdMismatchError` deletes the device.
- **Client:** `web/sw.js` shows every push (data-only messages, always displayed, because iOS revokes permission from pushes that show nothing) and focuses the app on tap; it also keeps the offline app shell ([code map](../architecture/code-map.md)); registered at every launch as `/sw.js?v=<APP_VERSION>`. The More panel's Reminders button needs a tap for the iOS permission prompt. `web/push.js` uses the Firebase messaging SDK with FCM's default VAPID key (`VAPID_KEY` empty).
- **Setup:** `scripts/setup-push.sh` (also enables Cloud Tasks, creates the queue, grants the runtime account `cloudtasks.enqueuer` on it and `serviceAccountUser` on the caller identity, sets `REMINDER_QUEUE`; [deploy](../ops/deploy.md)). Test the digest with `gcloud scheduler jobs run now-notify --location us-central1`.

**Budget alerts (2026-09-21).** `POST /internal/budget-alert` receives a Cloud Billing budget notification from Pub/Sub (topic `<service>-budget-alerts`, push subscription `<service>-budget-push`, both made by `scripts/setup-cost-guards.sh`; needs `setup-push.sh` first). It is OIDC-verified exactly like `/internal/notify` (same `NOTIFY_CALLER` identity and audience; Pub/Sub's service agent needs `serviceAccountTokenCreator` on it). Unlike reminders it sends **at any hour**, to every device, when a threshold is crossed (1%, 50%, 100% actual, 100% forecast of the $1 budget): title `GCP COST ALERT`, body like `$0.03 spent of the $1.00 budget (1%) this month. Run scripts/cost-check.sh.`. Routine spend updates (no threshold) are ignored; each threshold pushes once per month (marker `budget:<month>:<kind>:<fraction>`, 35-day TTL). Code: `push.budget_push` / `push.run_budget_alert`. See [principles](../principles.md).
- **Types:** digest, heads-up scheduling and `run_heads_up` require the `notifies` capability, so a `list`/`project` with a leftover due date sends nothing ([item types](item-types.md)).
